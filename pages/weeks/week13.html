🧠 Theory & Concepts

1. Tokenisation Taxonomies

Tokenisation breaks continuous text strings into individual semantic units called tokens . There are three main levels of granularity:

  • Word Tokenisation: Splits text by whitespace and punctuation. Simple but prone to massive vocabularies and Out-of-Vocabulary (OOV) issues.
  • Character Tokenisation: Breaks text into individual letters. Vocabulary is tiny, but sequences become extremely long, losing semantic context.
  • Subword Tokenisation: (WordPiece, Byte-Pair Encoding) Breaks rare words into meaningful sub-units (e.g. "embeddings" $\rightarrow$ ["embed", "##dings"] ). This is the standard in modern LLMs.

2. Stemming vs. Lemmatisation

To reduce vocabulary size, we map different inflectional forms of a word back to a common base:

Feature Stemming (e.g. Porter Stemmer) Lemmatisation (e.g. spaCy)
Mechanism Heuristic-based suffix chopping using regular patterns. Morphological analysis backed by lexical databases (WordNet).
Output Often non-dictionary words (e.g. "studying" $\rightarrow$ "studi" ). Valid dictionary base words (e.g. "better" $\rightarrow$ "good" ).
Speed Extremely fast (simple regex-like rules). Slower (requires POS tagging & lookup).
Accuracy Low (over-stemming/under-stemming issues). High (preserves semantic context).

3. Porter Stemming Rule Formulation

The Porter stemmer operates in 5 consecutive phases of replacement rules. For example, Phase 1a defines:

$$\begin{aligned} \text{SSES} &\rightarrow \text{SS} \quad (\text{e.g. caresses} \rightarrow \text{caress}) \\ \text{IES} &\rightarrow \text{I} \quad (\text{e.g. ponies} \rightarrow \text{poni}) \\ \text{SS} &\rightarrow \text{SS} \quad (\text{e.g. caress} \rightarrow \text{caress}) \\ \text{S} &\rightarrow \emptyset \quad (\text{e.g. cats} \rightarrow \text{cat}) \end{aligned}$$ Deterministic suffix chopping rules.

4. Levenshtein (Edit) Distance Formulation

During spell-checking and text normalisation, we measure the similarity of two strings $a$ and $b$ using the Levenshtein Distance . The distance between $a$ (of length $i$) and $b$ (of length $j$) is calculated using the recurrence relation:

$$\text{lev}_{a,b}(i, j) = \begin{cases} \max(i, j) & \text{if } \min(i, j) = 0, \\ \min \begin{cases} \text{lev}_{a,b}(i-1, j) + 1 \\ \text{lev}_{a,b}(i, j-1) + 1 \\ \text{lev}_{a,b}(i-1, j-1) + [a_i \neq b_j] \end{cases} & \text{otherwise.} \end{cases}$$ Where $[a_i \neq b_j]$ is 0 if characters match, and 1 if they differ. This covers insertion, deletion, and substitution operations.

Below is a pure-NumPy implementation of the Levenshtein Distance matrix calculation, illustrating how the dynamic programming grid computes optimal transformation alignments between messy inputs and target forms:

# Step 1: Algorithmic Implementation & Core Transformations
import numpy as np

def levenshtein_distance(seq1, seq2):
    size_x = len(seq1) + 1
    size_y = len(seq2) + 1
    matrix = np.zeros((size_x, size_y), dtype=np.int32)
    
    for x in range(size_x):
        matrix[x, 0] = x
    for y in range(size_y):
        matrix[0, y] = y
        
    for x in range(1, size_x):
        for y in range(1, size_y):
            if seq1[x-1] == seq2[y-1]:
                matrix[x, y] = matrix[x-1, y-1]
            else:
                matrix[x, y] = min(
                    matrix[x-1, y] + 1,    # Deletion
                    matrix[x, y-1] + 1,    # Insertion
                    matrix[x-1, y-1] + 1   # Substitution
                )
    return matrix[size_x-1, size_y-1]

print("Distance between 'kitten' and 'sitting':", levenshtein_distance("kitten", "sitting"))
print("Distance between 'studying' and 'studi':", levenshtein_distance("studying", "studi"))

🧠 Theory & Concepts

1. Bag of Words (BoW) & Sparsity Constraints

The Bag of Words (BoW) representation maps a document to a vector of token occurrences. If the training corpus has a vocabulary size of $V = 50,000$ unique words, every single document is converted into a $50,000$-dimensional vector. Since most documents contain only 50-100 unique words, $99.9\%$ of the vector elements are zeros. This creates severe sparsity constraints , bloating RAM usage and making computational weights highly fragile.

2. TF-IDF Mathematical Formulations

To prevent extremely common words (like "the" , "is" , "and" ) from dominating representations, TF-IDF scales occurrences down if they appear across many documents. The exact equations are formulated as follows:

$$\text{TF}(t, d) = \frac{f_{t,d}}{\sum_{t' \in d} f_{t',d}}$$ Term Frequency: occurrence of term $t$ in document $d$ relative to document size.
$$\text{IDF}(t, D) = \log\left( \frac{1 + N}{1 + \text{DF}(t)} \right) + 1$$ $Inverse Document Frequency: where $N$ is total documents, and $\text{DF}(t)$ is number of documents containing term $t$. Adding 1 avoids division-by-zero.$
$$\text{TF-IDF}(t, d, D) = \text{TF}(t, d) \times \text{IDF}(t, D)$$ Final TF-IDF weight balances term specificity and local occurrence.

3. Dimensionality Reduction: Latent Semantic Analysis (LSA)

To resolve BoW sparsity and synonymy issues, we apply Latent Semantic Analysis (LSA) . LSA takes our sparse term-document matrix $X$ of size $V \times N$ and decomposes it into three matrices using Singular Value Decomposition (SVD) :

$$X = U \Sigma V^T$$ Where $U$ ($V \times k$) represents term concepts, $\Sigma$ ($k \times k$) contains concept strengths, and $V^T$ ($k \times N$) holds document concepts, reducing variables to $k \ll V$ dense features.

4. N-grams Context Extraction

Traditional BoW models treat words independently, losing all structural sequence. N-grams capture immediate local context by grouping adjacent words:

  • Unigrams (1-grams): ["the", "quick", "brown"]
  • Bigrams (2-grams): ["the quick", "quick brown"]
  • Trigrams (3-grams): ["the quick brown"]

While N-grams preserve simple structural dependencies (e.g. mapping "not good" differently from "good" ), they explode vocabulary size exponentially, scaling sparsity constraints.

# Complete solution for: Build a TF-IDF vectoriser from scratch in NumPy

import numpy as np
from collections import Counter
import math

class TFIDFVectorizer:
    """TF-IDF Vectorizer from scratch using NumPy."""
    def __init__(self):
        self.vocabulary_ = {}
        self.idf_ = None
    
    def _tokenize(self, text):
        """Simple whitespace + lowercase tokenization."""
        return text.lower().split()
    
    def fit(self, documents):
        """Build vocabulary and compute IDF."""
        # Build vocabulary
        vocab = set()
        for doc in documents:
            vocab.update(self._tokenize(doc))
        self.vocabulary_ = {word: i for i, word in enumerate(sorted(vocab))}
        
        # Compute IDF: log(N / df(t)) + 1 (smooth IDF)
        N = len(documents)
        df = np.zeros(len(self.vocabulary_))
        for doc in documents:
            seen = set(self._tokenize(doc))
            for word in seen:
                if word in self.vocabulary_:
                    df[self.vocabulary_[word]] += 1
        
        self.idf_ = np.log(N / (df + 1)) + 1  # Smooth IDF
        return self
    
    def transform(self, documents):
        """Convert documents to TF-IDF matrix."""
        matrix = np.zeros((len(documents), len(self.vocabulary_)))
        
        for i, doc in enumerate(documents):
            tokens = self._tokenize(doc)
            tf = Counter(tokens)
            for word, count in tf.items():
                if word in self.vocabulary_:
                    j = self.vocabulary_[word]
                    matrix[i, j] = (count / len(tokens)) * self.idf_[j]
        
        # L2 normalize
        norms = np.linalg.norm(matrix, axis=1, keepdims=True)
        norms[norms == 0] = 1
        matrix /= norms
        
        return matrix
    
    def fit_transform(self, documents):
        return self.fit(documents).transform(documents)

🧠 Theory & Concepts

1. Continuous Bag of Words (CBOW) vs. Skip-gram

Word2Vec uses shallow two-layer neural networks to learn dense embeddings:

  • CBOW (Continuous Bag of Words): Predicts a target center word $w_t$ from surrounding context words within window size $C$:
    $\text{Input Context: } \{w_{t-C}, \dots, w_{t+C}\} \rightarrow \text{Output Center: } w_t$
    Faster to train, represents frequent words slightly better.
  • Skip-gram: Predicts context words from the single center word $w_t$:
    $\text{Input Center: } w_t \rightarrow \text{Output Context: } \{w_{t-C}, \dots, w_{t+C}\}$
    Slower, but represents rare words and semantic analogies significantly better.

2. Skip-gram with Negative Sampling (SGNS) Formulation

Calculating full Softmax denominators over vocabulary $V$ (often 100k+ words) is computationally prohibitive. Negative Sampling solves this by converting the multi-class problem into binary logistic classification. For a center word $w$ and context word $c$, the positive label is 1; for $k$ randomly sampled "negative" words $w_i$, the label is 0. The SGNS loss function is formulated as:

$$\mathcal{L}_{\text{SGNS}} = -\log \sigma(v'_{w_O}^\top v_{w_I}) - \sum_{i=1}^k \mathbb{E}_{w_i \sim P_n(w)} \left[ \log \sigma(-v'_{w_i}^\top v_{w_I}) \right]$$ Where $v_{w_I}$ is the input vector of center word $w_I$, $v'$ is the output representation, and $P_n(w)$ is the noise distribution (vocabulary frequencies raised to the power of $\frac{3}{4}$ to boost rare word selection).

3. Hierarchical Softmax Huffman Coding Tree

Hierarchical Softmax structures vocabulary as a leaf-node binary Huffman Tree , where frequent words reside near the root and rare words deeper down. The probability of choosing a word $w$ is defined as path traversal multiplications:

$$P(w \mid w_I) = \prod_{j=1}^{L(w)-1} \sigma\left( \text{ch}(n(w, j)) \cdot \theta_{n(w, j)}^\top v_{w_I} \right)$$ Where $L(w)$ is path length, $n(w, j)$ is node $j$ on the path, and $\text{ch}(n)$ maps left (+1) or right (-1) tree step choices. This scales search time logarithmically to $O(\log_2 V)$.

4. GloVe: Global Vectors Formulation

While Word2Vec trains on local sliding windows (ignoring global co-occurrences), GloVe trains directly on the global co-occurrence matrix $X$, where $X_{i,j}$ is the count of word $j$ appearing in the context of word $i$. The GloVe loss function is defined as:

$$\mathcal{L}_{\text{GloVe}} = \sum_{i,j=1}^V f(X_{i,j}) \left( w_i^\top \tilde{w}_j + b_i + \tilde{b}_j - \log X_{i,j} \right)^2$$ Where $w_i, \tilde{w}_j$ are word vectors, $b_i, \tilde{b}_j$ are biases, and $f(x)$ is a weighted scaling function limiting the impact of extremely common co-occurrences.

def cosine_similarity(v1, v2):
    dot_prod = np.dot(v1, v2)

import torch
import torch.nn as nn
import torch.nn.functional as F
from collections import Counter
import numpy as np

class SkipGram(nn.Module):
    """Word2Vec Skip-Gram with Negative Sampling."""
    def __init__(self, vocab_size, embedding_dim):
        super().__init__()
        self.center_embeddings = nn.Embedding(vocab_size, embedding_dim)
        self.context_embeddings = nn.Embedding(vocab_size, embedding_dim)
        nn.init.xavier_uniform_(self.center_embeddings.weight)
        nn.init.zeros_(self.context_embeddings.weight)
    
    def forward(self, center, context, negatives):
        """
        center: (batch,) - center word indices
        context: (batch,) - positive context word indices
        negatives: (batch, num_neg) - negative sample indices
        """
        center_emb = self.center_embeddings(center)      # (batch, dim)
        context_emb = self.context_embeddings(context)    # (batch, dim)
        neg_emb = self.context_embeddings(negatives)      # (batch, num_neg, dim)
        
        # Positive score
        pos_score = torch.sum(center_emb * context_emb, dim=1)
        pos_loss = -F.logsigmoid(pos_score)
        
        # Negative score
        neg_score = torch.bmm(neg_emb, center_emb.unsqueeze(2)).squeeze(2)
        neg_loss = -F.logsigmoid(-neg_score).sum(dim=1)
        
        return (pos_loss + neg_loss).mean()

This allows models to disambiguate homonyms. For example, in "She will bank the check" , "bank" is labeled as a VERB , whereas in "She walked to the bank" , it is labeled as a NOUN .

🧠 Theory & Concepts

1. Document-Level vs. Token-Level Labeling

Classification in NLP splits into two main structural topologies:

  • Document Classification: Maps a whole sequence of tokens $x = \{x_1, \dots, x_T\}$ to a single category label $y$. We compress token embeddings using pooling or recurrent final hidden states, followed by a Softmax layer.
  • Sequence Labeling: Maps each individual token $x_i$ to its own label $y_i$ (e.g., POS tagging, NER). The model must output a sequence of labels $y = \{y_1, \dots, y_T\}$ equal in length to the input.

2. Bidirectional LSTM-CRF Architecture

While a standard Softmax layer classifies each token independently, it fails to capture dependencies between adjacent labels (e.g. in NER, an I-ORG tag can never follow a B-PER tag). A Conditional Random Field (CRF) layer solves this by modeling joint sequence probabilities globally. A BiLSTM-CRF combines the contextual feature representation of a Bidirectional LSTM with the global sequence alignment constraints of a CRF. For an input sequence $x$ and a predicted label sequence $y$, the CRF score is calculated as:

$$S(x, y) = \sum_{i=0}^T A_{y_i, y_{i+1}} + \sum_{i=1}^T P_{i, y_i}$$ Where $P_{i, y_i}$ is the emission score of token $i$ output by the BiLSTM, and $A_{y_i, y_{i+1}}$ is the transition score of moving from label $y_i$ to $y_{i+1}$.

The conditional probability of the label sequence $y$ is:

$$P(y \mid x) = \frac{\exp(S(x, y))}{\sum_{y'} \exp(S(x, y'))}$$ Where the denominator sums over all possible label sequences (solved using the Viterbi dynamic programming algorithm).

3. Numerical Stability: Log-Sum-Exp Trick

When calculating the denominator partition function $Z(x) = \sum_{y'} \exp(S(x, y'))$, exponentiating raw transition and emission additions easily triggers numerical overflow on floating-point hardware. To ensure stable updates, we apply the Log-Sum-Exp Trick :

$$\log \sum_i \exp(v_i) = m + \log \sum_i \exp(v_i - m) \quad \text{where } m = \max(v)$$ By pulling out the maximum value $m$, we shift exponents down, bounding values within secure numerical precision ranges.

4. Classification Evaluation Metrics: Macro & Micro F1

For imbalanced text datasets, simple accuracy is a misleading metric. We must calculate Precision ($P$), Recall ($R$), and the F1-Score :

$$F_1 = 2 \times \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}} = \frac{2 \text{TP}}{2 \text{TP} + \text{FP} + \text{FN}}$$
  • Macro F1: Computes the F1-score independently for each class and averages them. Treats all classes equally, highlighting performance on rare labels.
  • Micro F1: Aggregates global True Positives, False Positives, and False Negatives first, then computes a single F1-score. Heavily influenced by common classes.

import torch.nn as nn

class BiLSTM_CRF(nn.Module):
    def __init__(self, vocab_size, tag_to_ix, embedding_dim, hidden_dim):
        super().__init__()
        self.embedding_dim = embedding_dim
        self.hidden_dim = hidden_dim
        self.vocab_size = vocab_size
        self.tag_to_ix = tag_to_ix
        self.tagset_size = len(tag_to_ix)

        self.embedding = nn.Embedding(vocab_size, embedding_dim)
        # Bidirectional LSTM
        self.lstm = nn.LSTM(
            embedding_dim, 
            hidden_dim // 2,
            num_layers=1, 
            bidirectional=True, 
            batch_first=True
        )
        
        # Map BiLSTM outputs to tag space (Emission scores)
        self.hidden2tag = nn.Linear(hidden_dim, self.tagset_size)

        # CRF Transition matrix parameter: A_ij is score of transitioning from tag j to tag i
        self.transitions = nn.Parameter(torch.randn(self.tagset_size, self.tagset_size))

    def _get_lstm_features(self, sentence):
        embeds = self.embedding(sentence) # Shape: (Batch, SeqLen, EmbedDim)
        lstm_out, _ = self.lstm(embeds)   # Shape: (Batch, SeqLen, HiddenDim)
        feats = self.hidden2tag(lstm_out)  # Shape: (Batch, SeqLen, TagsetSize)
        return feats

    def forward(self, sentence):
        # Get emission features from LSTM
        lstm_feats = self._get_lstm_features(sentence)
        return lstm_feats

import torch.nn as nn

def masked_cross_entropy_loss(logits, targets, masks):
    # CrossEntropyLoss with reduction='none' preserves values per token coordinate
    loss_fn = nn.CrossEntropyLoss(reduction='none')
    raw_loss = loss_fn(logits.view(-1, logits.size(-1)), targets.view(-1))

2. TextRank: Graph Centrality for Sentences

Unlike abstractive summarisation (which generates new text), Extractive Summarisation ranks existing sentences and extracts the top candidates. TextRank (Mihalcea & Tarau, 2004) frames a document as a graph where each sentence $S_i$ is a vertex. An edge's weight represents the semantic similarity between sentences $S_i$ and $S_j$. The dynamic PageRank centrality score for sentence $S_i$ is iteratively computed as:

$$\text{Score}(S_i) = (1 - d) + d \sum_{j \in \text{In}(S_i)} \frac{\text{Similarity}(S_i, S_j)}{\sum_{k \in \text{Out}(S_j)} \text{Similarity}(S_k, S_j)}$$ Where $d$ is the damping factor (typically set to 0.85) representing the probability of a reader randomly jumping to another sentence, and $\text{Similarity}(S_i, S_j)$ is the edge weight.

3. Sentence Similarity Adjacency Formulation

The similarity score between two sentences $S_i$ and $S_j$ is calculated based on the overlap of their token vocabularies, normalized by length to prevent bias toward long sentences:

$$\text{Similarity}(S_i, S_j) = \frac{|\{w \mid w \in S_i \ \& \ w \in S_j\}|}{\log(|S_i|) + \log(|S_j|)}$$ Word overlap similarity. Alternatively, we can use the cosine similarity of their dense sentence embeddings.

import numpy as np
import re

def sentence_similarity(sent1, sent2):
    # Tokenise words by splitting on non-alphanumeric characters
    words1 = set(re.findall(r"\w+", sent1.lower()))
    words2 = set(re.findall(r"\w+", sent2.lower()))
    
    if len(words1) == 0 or len(words2) == 0:
        return 0.0
        
    overlap = len(words1.intersection(words2))
    # Symmetric log normalisation
    denominator = np.log(len(words1) + 1e-5) + np.log(len(words2) + 1e-5)
    return overlap / (denominator + 1e-5)

def extract_summary(text, num_sentences=2, max_iter=50, d=0.85):
    # 1. Split text into clean sentences
    sentences = [s.strip() for s in re.split(r"[.!?]", text) if s.strip() != ""]
    n = len(sentences)
    if n <= num_sentences:
        return text
        
    # 2. Build similarity adjacency matrix
    similarity_matrix = np.zeros((n, n))
    for i in range(n):
        for j in range(n):
            if i != j:
                similarity_matrix[i][j] = sentence_similarity(sentences[i], sentences[j])
                
    # 3. Normalise row transitions to represent Markov jump dynamics
    for i in range(n):
        row_sum = np.sum(similarity_matrix[i])
        if row_sum > 0:
            similarity_matrix[i] /= row_sum

    # 4. Power iteration convergence loop
    scores = np.ones(n) / n
    for _ in range(max_iter):
        new_scores = (num_sentences - d) + d * similarity_matrix.T.dot(scores)
        if np.allclose(scores, new_scores, atol=1e-5):
            break
        scores = new_scores

    # 5. Extract top ranked sentences
    ranked_indices = np.argsort(scores)[::-1]
    top_indices = sorted(ranked_indices[:num_sentences])
    summary = ". ".join([sentences[idx] for idx in top_indices]) + "."
    return summary
