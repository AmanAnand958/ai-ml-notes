🎯 FAANG Autonomous Agent Interview Questions

Q1: How does the ReAct framework prevent hallucinated execution loops compared to pure Plan-and-Solve?

Plan-and-Solve generates a static multi-step plan upfront. If step 2 fails or returns unexpected data, subsequent steps fail cascade-style. ReAct interleaves reasoning (Thought) with dynamic tool execution (Action) and real environmental feedback (Observation), allowing the model to adapt its plan dynamically after every step.

Q2: What is the primary operational risk of giving agents unrestricted Python execution tools?

Remote Code Execution (RCE) and infinite compute loops. Production agents must execute generated code inside ephemeral sandboxes (e.g. gVisor, Firecracker microVMs, or E2B) with strict memory limits (e.g. 512MB), CPU timeouts (10s), and network egress restrictions.

Q1: Why is Pydantic output validation superior to regex-based JSON parsing for LLM pipelines?

Regex only verifies syntactical format, not semantic data integrity. Pydantic provides runtime type coercion, boundary checks (e.g. gt=0 ), enum matching, and generates detailed error messages that can be fed directly back into the LLM context for automatic self-correction.

⚠️ Gotcha: Pydantic Validation Retries on Schema Deviation

LLMs frequently omit required fields or produce malformed JSON under complex schemas; failing to configure `max_retries=3` in Instructor results in unhandled runtime ValidationErrors.

python 
# Step 1: Algorithmic Implementation & Core Transformations
import instructor
from pydantic import BaseModel, Field, field_validator
from openai import OpenAI
from typing import List

class LineItem(BaseModel):
    description: str
    amount: float = Field(gt=0, description="Item cost in USD")

class Invoice(BaseModel):
    invoice_number: str
    items: List[LineItem]
    total: float

    @field_validator("total")
    def verify_total(cls, v, values):
        items = values.data.get("items", [])
        expected = sum(item.amount for item in items)
        if abs(v - expected) > 0.01:
            raise ValueError(f"Total {v} does not equal sum of items {expected}")
        return v

client = instructor.from_openai(OpenAI())
invoice = client.chat.completions.create(
    model="gpt-4o-mini",
    response_model=Invoice,
    max_retries=3,
    messages=[{"role": "user", "content": "Billed ACME Corp for 2 servers at $400 each and $150 setup fee. Total: $950. Inv #9921."}]
)
print(f"Validated Invoice: {invoice.invoice_number} | Total: ${invoice.total}")

🏢 Enterprise Case Study: Stateful Code Generation in GitHub Copilot Workspace

GitHub Copilot Workspace executes complex multi-file pull request workflows using cyclical state graphs. The state object holds the workspace repository tree, modified diffs, test outputs, and compiler error traces. ⚠️ Gotcha: Stateless Graph Memory Loss

LangGraph nodes operate statelessly by default; if you do not attach a persistent checkpointer (e.g. `MemorySaver` or `PostgresSaver`), multi-turn conversation state will be completely erased between user requests.

python 
# Step 1: Algorithmic Implementation & Core Transformations
from typing import TypedDict, Annotated
import operator
from langgraph.graph import StateGraph, START, END

class AgentState(TypedDict):
    messages: Annotated[list, operator.add]
    next_step: str
    retry_count: int

def triage_node(state: AgentState) -> dict:
    last_msg = state["messages"][-1]
    if "error" in last_msg.lower():
        return {"next_step": "debugger", "retry_count": state.get("retry_count", 0) + 1}
    return {"next_step": "responder"}

def debugger_node(state: AgentState) -> dict:
    return {"messages": ["Fixed error: patched null pointer."]}

def responder_node(state: AgentState) -> dict:
    return {"messages": ["Request processed successfully."]}

workflow = StateGraph(AgentState)
workflow.add_node("triage", triage_node)
workflow.add_node("debugger", debugger_node)
workflow.add_node("responder", responder_node)

workflow.add_edge(START, "triage")
workflow.add_conditional_edges("triage", lambda s: s["next_step"], {"debugger": "debugger", "responder": "responder"})
workflow.add_edge("debugger", "responder")
workflow.add_edge("responder", END)

app = workflow.compile()
out = app.invoke({"messages": ["Fatal error on line 42"], "retry_count": 0})
print("Final State:", out["messages"])
