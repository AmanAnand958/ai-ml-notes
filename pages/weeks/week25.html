Q1: What role does the NVIDIA GPU Operator play in Kubernetes cluster management?

The GPU Operator automates the installation and lifecycle management of the NVIDIA driver, NVIDIA Container Toolkit, K8s device plugin, and DCGM monitoring exporter as containerized DaemonSets across all GPU nodes.

Q2: How does the Kubeflow PyTorchJob custom resource controller handle node worker failures in DDP?

🏢 Enterprise Case Study: Keda GPU-Metric Auto-scaling

Traditional Kubernetes HPA scales on CPU/RAM, which is inadequate for GPU workloads. Enterprise clusters use KEDA (Kubernetes Event-driven Autoscaling) to scale inference pods based on Prometheus metrics like DCGM_FI_DEV_GPU_UTIL and queue request depths.

📐 Mathematical Deep-Dive: KEDA Proportional-Integral Autoscaling Control Function

$$R(t) = \left\lceil R(t-1) + K_p e(t) + K_i \int_0^t e(\tau) d\tau \right\rceil \quad \text{where } e(t) = \text{Metric}(t) - \text{Target}$$

Prevents pod flapping and over-provisioning during transient inference traffic spikes.

nvidia.com/gpu limit
K8s resource limit that requests N physical GPUs for a pod. Must match the number of GPUs the container needs.
PersistentVolumeClaim (PVC)
A request for durable storage that persists across pod restarts. Essential for model weight caches.
nodeSelector
Constrains a pod to only be scheduled on nodes with matching labels (e.g., accelerator: nvidia-a100 ).

HPA (Horizontal Pod Autoscaler)
Automatically adds/removes pod replicas based on CPU, memory, or custom metrics.
KEDA
Kubernetes Event-Driven Autoscaling. Extends HPA to scale on external events like Kafka topics, SQS queues, Prometheus metrics.
Scale-to-Zero
KEDA can scale to 0 replicas when a queue is empty, saving cost. Standard HPA minimum is 1.
